## Episode 4: The Secret Language of LLMs

### Why LLMs Need Tokens

**Computers Cannot Directly Understand Words**

- When we give a sentence to an LLM, it doesn't process it as-is.
- Instead, the text is broken down into smaller units called **tokens**.

**Example: How a Sentence Becomes Tokens**

- Sentence: `"Namaste AI is amazing"`
- Gets converted into Token IDs, e.g.: `[45, 321, 4594, 5552, 318, 4593]`
- These Token IDs are then passed into the LLM.

**What Is a Token?**

- A token is a unit of text defined by a **Tokenizer**.
- Important: **1 word ≠ 1 token** (not necessarily true — a word can be split into multiple tokens, or multiple words can combine into fewer tokens).
- A Tokenizer is simply an algorithm that converts text into tokens.
- Tools like OpenAI's Tokenizer or Tiktokenizer let you visualize exactly how text is broken into tokens.

---

### Why Subword Tokenization?

**Why Models Use Subword Tokenization**

- Subword tokenization strikes a balance — it converts commonly used chunks of text into single tokens, rather than tokenizing whole words or single characters.
- Example: A word like "untrustable" might be split into meaningful subword pieces (like "un" + "trust" + "able") so the model can reuse those pieces across many different words.

**Why Not One Token Per Word?**

- Since any language can have practically infinite words, creating a unique token for every possible word would require a massive, unmanageable vocabulary.

**Why Not One Token Per Character?**

- Character-level tokenization only needs a small set of tokens (e.g., a-z, 0-9), but it generates a huge number of tokens for even a short sentence — making processing far less efficient.

**Vocabulary & Token ID**

- Every tokenizer has a fixed **Vocabulary** — the full collection of tokens it knows how to represent directly.
- Simplified example vocabulary:

| Token | ID |
|-------|-----|
| "the" | 10 |
| "is" | 12 |
| "jaan" | 13 |
| "Sochi" | 14 |
| "ing" | 15 |

### Tokenizers, Special Tokens & BPE

**Tokenization Has No Inherent Meaning**

- Tokenization simply breaks a sentence into reusable chunks — it does not assign meaning.
- Because of this, two sentences with the same meaning can produce completely different tokens depending on the tokenizer used.
- Example: The phrase "This is a big..." might show as 4 tokens in a tokenizer visualizer, but consume a different number of tokens once actually processed by ChatGPT (since extra special tokens get added behind the scenes).

**Special Tokens**

Beyond regular text tokens, models add special tokens for structure, such as:
- System Instruction
- Chat/Message
- End of Message
- Tool Output
- End of Output

**Popular Tokenizer Encodings**

| Encoding | Vocabulary Size | Used By |
|----------|-----------------|---------|
| r50k_base | ~50,000 tokens | GPT-3, text-davinci-001 |
| p50k_base | ~50,000 tokens (+ extra code tokens) | Code-generation & older text models (e.g., text-davinci-003) |
| cl100k_base | ~100,000 tokens | GPT-3.5-turbo, GPT-4o-mini |
| o200k_base (latest) | ~200,000 tokens | Newer flagship models like GPT-4o, o1, o3 series |

**Byte Pair Encoding (BPE)**

- BPE builds a vocabulary by repeatedly merging the most frequently occurring neighboring pairs of characters/subwords.
- Each time a pair occurs frequently enough, it gets merged into a new single token and added to the vocabulary.

### The Context Window

**What Is a Context Window?**

- A Context Window is the total amount of tokenized information a model can process within one active generation request.
- A language model does not have unlimited memory — every model has a limit on how many tokens it can process at a time.

**What Counts Toward the Context Window**

- System instructions
- Your current prompt
- Retrieved information
- Tool outputs
- The model's generated response
- All of these together consume tokens from the same shared limit.

**Common Myths — Busted**

- Long Prompt ≠ Better Results
- One token ≠ one word
- Every model uses the same tokenizer — ❌ False
- Token ID represents meaning — ❌ False
- One visible emoji = one token — ❌ False
- More tokens always = better answer — ❌ False
- A larger vocabulary is always better — ❌ False

**Context Retention Example**

- Prompt 1: "I'm in Patna"
- Prompt 2 (later): "How is the weather?"
- Because the context window retains earlier conversation, ChatGPT understands this is asking about the weather **in Patna** specifically — it remembers the earlier detail from the same context window.

**What Happens When the Context Window Fills Up?**

- Different applications handle this differently — there's no single universal approach.
- Common strategies include:
  - Truncating older parts of the conversation
  - Removing older messages entirely
  - Summarizing older conversation turns to free up space

---

### Key Takeaway

LLMs never actually "read" our words — they read tokens, produced by breaking text into subword chunks via a tokenizer. Every model has a fixed vocabulary and a limited context window, and everything in a conversation (instructions, prompts, retrieved data, tool outputs, and the response itself) shares that same limited token budget. More tokens or a bigger vocabulary doesn't automatically mean a better answer — it's about how efficiently that shared space is used.
